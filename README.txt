DZ Game Market — نسخة مع لوحة مسؤول متصلة بـ Supabase
=======================================================

المميزات
--------
- لوحة مسؤول على admin.html لإضافة/تعديل/حذف العروض دون تعديل الكود.
- قسم الحسابات: اسم اللعبة، عنوان الحساب، صورة رئيسية، صور إضافية متعددة، وصف، سعر، وروابط تواصل البائع.
- قسم الشحن: اسم اللعبة، صورة أسعار الشحن، سعر اختياري، وروابط تواصل البائع.
- خيار «عرض ترويجي مثبت» لعروض الشحن؛ تظهر العروض المفعّل لها الخيار قبل العروض العادية.
- الصور تحفظ في Supabase Storage، وبيانات المنتجات في جدول products.
- الموقع يعرض تلقائيًا المنتجات النشطة التي يضيفها المسؤول.
- مفتاح Publishable في المتصفح وليس مفتاح service_role.

إعداد لمرة واحدة
----------------
1. افتح مشروع Supabase المرتبط بالموقع.
2. من Authentication > Users تأكد من وجود حساب المسؤول وأن UID يطابق الموجود في js/admin.js وsupabase-setup.sql.
   UID المجهز حاليًا: 1e389dfb-a16b-438e-a1c8-4468bd308148
3. افتح SQL Editor والصق كامل ملف supabase-setup.sql ثم Run.
   الملف ينشئ/يحدث جدول products وسياسات RLS وسياسات صور bucket product-images.
4. من Authentication تأكد أن حساب المسؤول يمكنه تسجيل الدخول بالبريد وكلمة المرور.
5. افتح الموقع عبر استضافة HTTPS أو خادم محلي؛ لا تفتح الملفات عبر file://.
6. افتح admin.html وسجّل الدخول. ابدأ بإضافة منتج تجريبي، ثم افتح index.html للتحقق من ظهوره.

تشغيل محلي
----------
إذا كان Python مثبتًا، افتح الطرفية داخل مجلد المشروع وشغّل:
python -m http.server 8000
ثم افتح:
http://localhost:8000
لوحة المسؤول:
http://localhost:8000/admin.html

مهم
----
- حافظ على ترتيب المجلدات js وcss.
- اسم bucket يجب أن يكون product-images.
- الصور المدعومة JPG وPNG وWebP، بحد أقصى 5MB للصورة.
- ضع رابط كل حساب تواصل في سطر مستقل.
- خيار الترويج مخصص لقسم الشحن فقط، وترتيب العروض المثبتة يكون في الأعلى.
- مفتاح sb_publishable_ مخصص للواجهة، لكن أمان البيانات يعتمد على سياسات RLS؛ لا تضف service_role أو secret key إلى ملفات الموقع.
- عند حذف منتج تُحذف بياناته من جدول المنتجات، لكن قد تبقى الصور المرفوعة في Storage؛ يمكن تنظيفها لاحقًا من Storage.
- الطلبات القديمة والسلة المحلية تبقى كما كانت؛ هذه الإضافة تدير كتالوج المنتجات والصور فقط.


ميزات إضافية:
- قسم الوسطاء في الصفحة الرئيسية مع صورة وروابط Facebook وWhatsApp وInstagram وTikTok.
- إدارة الوسطاء من لوحة admin.html (إضافة/تعديل/حذف/إظهار أو إخفاء).
- أسعار المنتج: الدينار الجزائري، الدولار، والفليكسي.
- مفاتيح لتحديد طرق الدفع المدعومة، وإظهار رسالة "لا ندعم هذه الطريقة" عند تعطيلها.

التثبيت:
1) احتفظ بنسخة احتياطية من المشروع.
2) في Supabase SQL Editor نفّذ ملف supabase-migration-mediators-pricing.sql مرة واحدة.
3) افتح admin.html وسجّل الدخول بحساب المسؤول لإدارة المنتجات والوسطاء.
4) إذا ظهر خطأ صلاحيات، لا تحذف جدول products؛ أرسل نص الخطأ للمراجعة.


التعديلات الإضافية دون حذف قسم الوسطاء:
- المظهر: أزرار الشمس/القمر/الأبيض والأسود في الشريط العلوي.
- روابط التواصل العامة: افتح js/site-customizations.js وعدّل القيم داخل contactLinks (WhatsApp/Facebook/Instagram/TikTok).
- الشروط والأحكام: النص موجود داخل متغير terms في js/site-customizations.js ويمكنك تعديله.
- روابط البائع: من لوحة التحكم أضف كل رابط في سطر منفصل في حقل روابط حساب البائع.
- تم حذف زر شراء الآن من بطاقات الحسابات فقط؛ قسم الشحن والوسطاء ولوحة الإدارة وإعدادات Supabase محفوظة.


تحويل العمليات الإدارية إلى Backend (Node.js)
--------------------------------------------
- عمليات إضافة/تعديل/حذف المنتجات والوسطاء ورفع الصور تمر الآن عبر server.js.
- المفتاح السري SUPABASE_SECRET_KEY يُقرأ من .env على الخادم فقط ولا يُضمّن في ملفات المتصفح.
- ملف js/supabase-client.js ما زال يحتوي على URL ومفتاح Publishable عام؛ هذا طبيعي لأن تسجيل الدخول وقراءة الكتالوج العام يعملان من المتصفح. لا تضع فيه service_role أو sb_secret.

تشغيل الخادم:
1) انسخ .env.example إلى .env.
2) ضع SUPABASE_URL وSUPABASE_PUBLISHABLE_KEY وSUPABASE_SECRET_KEY وADMIN_UID في .env.
3) من مجلد aaa شغّل: npm install
4) ثم: npm start
5) افتح http://localhost:3000 (ولا تفتح index.html باستخدام file://).

الأمان:
- لا ترفع .env إلى Git أو الاستضافة العامة؛ .gitignore يستثنيه.
- SUPABASE_SECRET_KEY يجب أن يكون مفتاحًا سريًا من Supabase ويظل على الخادم. إذا كان مفتاحك من نوع service_role القديم فتعامل معه كسر شديد الحساسية.
- API يتحقق من جلسة Supabase ومن ADMIN_UID قبل أي عملية إدارية. لا تعتمد على إخفاء عناصر الواجهة كوسيلة حماية.
- نشر الإنتاج يحتاج HTTPS وإعداد متغيرات البيئة في منصة الاستضافة، وليس رفع ملف .env ضمن الملفات العامة.


إعداد أمني للـBackend
---------------------
- انسخ .env.example إلى ملف اسمه .env بجانب server.js ثم أدخل المفاتيح الحقيقية محليًا.
- لا تضع SUPABASE_SECRET_KEY في ملفات JavaScript أو .env.example أو GitHub.
- إذا كُشف مفتاح Secret سابقًا، ألغِه من Supabase وأنشئ مفتاحًا جديدًا وحدّث .env.
- شغّل الخادم باستخدام npm install ثم npm start، وافتح الموقع من http://localhost:3000 وليس Live Server.
- إذا ظهر 403، تحقق من أن ADMIN_UID يطابق UUID لحساب المسؤول في Supabase Authentication > Users وأن جلسة الدخول تخص ذلك الحساب.
- ملفات .env وserver.js وملفات SQL وملفات إعداد الحزم لا تُقدّم للزوار عبر الخادم الثابت.

\nلوحة الإدارة المنفصلة محليًا
---------------------------
- الموقع العام: http://localhost:3000/
- لوحة الإدارة المنفصلة: http://localhost:3000/admin/
- ملفات لوحة الإدارة موجودة داخل admin-panel/ بدل جذر الموقع.
- هذا فصل في المسار والملفات، وليس نطاقًا مستقلًا بعد. يمكن لاحقًا نشر لوحة الإدارة على نطاق فرعي منفصل مع ضبط CORS وبيئة الخادم.
- لا ترفع ملف .env أو node_modules إلى GitHub. أنشئ .env من .env.example وأدخل القيم محليًا.
